That standalone artifact did not exist in the repository when the audit was performed. `docs/architecture/EXPANSION_ERA_REFRESH.md` explicitly flagged this and instructed adding the plan before UI implementation begins.

Until the plan landed, the authoritative substitute was the "Future UI Polish Roadmap" section of `DESIGN.md`, reinforced by the minimum sequence in `docs/architecture/EXPANSION_ERA_V2.md` and `docs/architecture/EXPANSION_ERA_REFRESH.md`. ## 1. Current UI Audit

### Routes that exist today

- `/` → `app/page.tsx` — the legacy chatbot composition. 1,486 lines, single client component, ~20 panels stacked under a `max-w-3xl` chat column.
- `/rest`, `/working`, `/audit` (plus `audit/architecture-graph`, `audit/governance-boundaries`, `audit/red-team-sandbox`, `audit/telemetry-cockpit`) — cockpit-shaped surfaces. `DESIGN.md` already says these are "much closer to the desired design language."
- Layout: `app/layout.tsx` — minimal, no font import, no token boot.
- Global CSS: `app/globals.css` — Tailwind v4 `@theme inline` block with hardcoded `Arial, Helvetica, sans-serif` at lines 11 and 25, light-mode `#ffffff`/`#171717` defaults, dark mode flipped via `prefers-color-scheme`. No JARVIS design tokens present.

### Chatbot tells, concretely

Grep found only two files in `app/` carrying the bubble-soup pattern: `globals.css` (Arial × 2) and `page.tsx` (13 hits for `bg-blue-600` / `bg-gray-900` / `max-w-3xl` / `rounded-xl`). The bubble code:

- `app/page.tsx:1248` — `<main className="min-h-screen bg-black text-white flex flex-col items-center justify-between p-6">`
- `app/page.tsx:1257-1262` — `bg-blue-600 ml-12` user bubble, `bg-gray-900 mr-12` assistant bubble — the exact anti-pattern called out in `DESIGN.md`.
- `app/page.tsx:1455` — `placeholder="Message JARVIS..."`, the "ordinary chat placeholder" called out in `DESIGN.md`.
- `app/page.tsx:1437-1449` — provider `<select>` dropdown next to the input — the "provider selector" anti-pattern in `DESIGN.md`.
- 16 panels (ApprovalCard, RuntimeCommandPanel, VoiceControlPanel, MemoryInspectorPanel, ProjectContinuityPanel, ConsentManifestPanel, PreferenceLedgerPanel, GoalContinuityPanel, TimelineIndexPanel, ReflectionPromptPanel, KeeperInterfacePanel, MemoryWeightingPreviewPanel, ConversationCuratorPanel, HumanReviewQueuePanel, MemoryCandidateReviewPanel, RollbackStatusPanel) render as a vertical stack below the chat thread — exactly the "card soup" in `DESIGN.md`.

### Typography

- App-wide font is Arial through `--font-sans` in `app/globals.css:11` and the body rule at `app/globals.css:25`.
- No `next/font` loader is wired in `app/layout.tsx`.
- No type-scale tokens (display / headline / title / body / label). `DESIGN.md` §3 defines the target scale but nothing in the code references it.

### Design tokens

- `DESIGN.md` frontmatter (lines 4-62) declares the canonical JARVIS palette, type, radii, spacing, and three component tokens. None of these are exposed in CSS variables or Tailwind theme. Tailwind's `@theme inline` only exposes `background`, `foreground`, `font-sans`, `font-mono`.
- No `tokens.css`, no `tailwind.config.*` overrides (Tailwind 4 is config-less and reads `@theme`), no `lib/design/tokens.ts`.
- 16 of 17 panel components contain at least one hardcoded `bg-blue-600` / `bg-gray-900` / `bg-gray-950` reference — semantic governance colors (emerald-local, amber-review, rose-blocked, cyan-signal, sky-focus) are nowhere in code.

### What is already aligned (must not regress)

- The cockpit pages `/rest`, `/working`, `/audit` and their sub-surfaces (telemetry-cockpit, governance-boundaries, architecture-graph, red-team-sandbox, verification-agent).
- Phase 21 contracts and approval lifecycle — UI.1-UI.4 are forbidden to touch any of this per `docs/architecture/EXPANSION_ERA_V2.md`.

## 3. Risks Carried Into Implementation

| #   | Risk                                                                                                                                       | Impact  | Mitigation                                                                                                     |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------- | -------------------------------------------------------------------------------------------------------------- |
| R1  | Missing UI Polish Plan artifact at audit time.                                                                                             | High    | UI.1 lands `UI_POLISH_PLAN.md`; downstream slices block on it.                                                 |
| R2  | Tailwind v4 `@theme inline` is the only config surface — schema mistakes break the whole stylesheet silently.                              | Med     | UI.2 adds a token drift test; dev-server visual smoke before commit.                                           |
| R3  | `next/font` adds a build-time dependency on Google Fonts download; offline builds may fail.                                                | Low-Med | `next/font/google` caches at build time; switch to `next/font/local` later if needed. Documented in UI.3 plan. |
| R4  | Moving the chat surface in UI.4 may break external links/bookmarks.                                                                        | Low     | The app has no public deployment. Internal only.                                                               |
| R5  | The current `/` chat composition contains 14 `useEffect` data loaders. A naive UI.4 move could double-fetch.                               | Med     | Hoist shared loaders into a server component or shared hook during UI.4; mark TODO.                            |
| R6  | Hidden assumption that every panel "belongs on `/`" — some flows (e.g. RuntimeCommandPanel) may be expected at app root for muscle memory. | Med     | UI.4 keeps panels reachable from `/`; only the chat bubble stream moves.                                       |
| R7  | Static "no-chatbot-tells" test could false-positive on legitimate semantic blue elsewhere.                                                 | Low     | Scope the regex to `app/page.tsx` and `app/converse/` only.                                                    |
| R8  | Decision drift — UI.5+ slices may want different fonts than UI.3 picks.                                                                    | Low     | Typography decision is recorded in `UI_POLISH_PLAN.md` so it is explicit and reversible.                       |
