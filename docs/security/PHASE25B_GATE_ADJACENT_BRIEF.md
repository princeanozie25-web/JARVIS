## 1. Threat model additions (Phase 24 method)

The gateway's existing controls are untouched. Realizing these three items adds **one new trust boundary** — an operator decides proposals from surfaces other than the originating chat stream — and one new process (the host). The attacks that boundary invites:

### EoP-16 — Operator-decision forgery from the cockpit [AMBER-PLANNED → drilled in E-046]

**Attack:** any page/script on the machine POSTs an APPROVE for a pending execution id, or replays a stale decision, without the human having seen the canonical effect.
**Control:** a decision from the operator surface is **hash-bound and view-bound**: the server issues a short-TTL, single-use _decision token_ only when it renders the pending row to the loopback operator surface, bound to `(approval.id, canonical_effect_hash)`; the decide call must present it and the hash it saw; FC-2 re-validation (expiry, scope-still-valid, client-still-active via the 24D-4 `currentGrant` lookup, hash-unchanged) runs exactly as for the chat inlet; a hash mismatch or expired/consumed decision token is a uniform denial. The Phase 18 lifecycle gains NO state: the decision token is a second, additive credential kind for the SAME `pending → approved|denied` transition, verified before `decideApprovalByExecution` is entered through the frozen `resumeApproval`.
**Drill:** forged id → denied; replayed token → denied; wrong hash → denied; token issued for row A used on row B → denied; decision after FC-2 revalidation failure → invalid, row untouched.

### EoP-17 — Origin / cross-site decision [AMBER-PLANNED → drilled in E-046]

**Attack:** a remote page in the same browser posts to the loopback decision route.
**Control:** the route is loopback-only, rejects non-same-origin (`Origin`/`Sec-Fetch-Site`) requests, and the decision token is never readable cross-origin. **Drill:** cross-origin POST → 403 uniform.

### EoP-18 — Host seam inversion [AMBER-PLANNED → drilled in E-045]

**Attack:** the host injects a seam that leaks or widens (e.g. a queue-status source that returns per-client detail, or a mute store a client can flip).
**Control:** the host injects **narrow projections only** (`() => number`, `(clientId) => number`, a mute store the gateway can only _read_ and a human can only _write_ via a host-side command), never the DB handle; the gateway graph stays GATE-2 clean (host lives in `scripts/`). **Drill:** the host's seams are pure functions over the DB with no client-settable input; GATE-2 and the 24E non-bypass drills stay green with the host present.

### ID-6 — Pending-row exposure on the operator surface [AMBER-PLANNED → drilled in E-046/E-047]

**Attack:** the cockpit renders raw tool input / client text as system truth (EoP-11 collapse) or leaks other clients' rows.
**Control:** the listing returns ONLY the trusted channel (server-derived `canonical_effect_json`, tool name, safety tag, expiry, client id) plus the **fenced** untrusted text; the existing `safeToolInputSummary` and the I-APJ2 presentation contract apply; per-client scoping is the operator's (all rows — the operator is the Gate), never a client's. **Drill:** the injection-framed payload from DRILL-3 renders fenced on the cockpit, never as JARVIS's recommendation.

### DoS — Host as a second flood inlet [covered by 24D-3]

The host wires `admissionLimits`, `clientMuteStore`, `pendingCountForClient` so the existing rate / quota / queue-depth / mute gates apply to real clients. **Drill:** admission counters observed live through the host.
