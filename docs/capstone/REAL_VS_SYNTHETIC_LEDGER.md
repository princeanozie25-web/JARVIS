# Real-vs-Synthetic Ledger — capstone-rendered surfaces

**Audit date:** 2026-07-05 · **HEAD at audit:** 2075feeb · **Read-only** (no code touched).
**Purpose:** one honest map of what each capstone-rendered surface actually shows, so the
capstone labels synthetic-by-design surfaces honestly instead of faking them as live.
This is the LIGHT pre-capstone pass; the full synthetic→real productionization audit is
Phase 25 (post-move).

## Classification key

| Class                         | Meaning                                                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **LIVE**                      | Reflects real runtime state (real rows, real store data, real probes).                                             |
| **DERIVED**                   | Computed from live data — real, just computed.                                                                     |
| **SYNTHETIC-BY-DESIGN (SBD)** | Deliberately static/fixture, for a recorded reason. Correct to stay synthetic unless Phase 25 decides otherwise.   |
| **SYNTHETIC-INCIDENTAL (SI)** | Static/fixture with no deliberate decision behind it — looks live-ish but isn't. These are the capstone-lie risks. |
| **CONDITIONAL**               | Live when a dependency is present/running; honest fallback otherwise. Capstone may see it honestly-empty in dev.   |

Context that frames everything below: the entire Next.js command-center surface
self-declares synthetic — the cockpit header renders `SYNTHETIC - METADATA-ONLY`
([WorkingCockpit.tsx:178](../../src/components/working/WorkingCockpit.tsx)) and every
model carries `SYNTHETIC_OBSERVABILITY_MARKER`
([liquid-command-center-data.ts:324](../../src/lib/command-center/liquid-command-center-data.ts),
[observability/synthetic-data.ts:13](../../src/lib/observability/synthetic-data.ts)).
The posture is honest at the surface level. The findings below are about **field-level**
honesty inside that frame, and about the live machinery that exists but is not rendered.

## Synthetic-incidental findings (the capstone-lie risks)

1. **`TESTS 4,930 PASS`** — `liquid-command-center-data.ts:327`. Stale count presented as a
   live-looking quality claim (real: 5,756). **Recommend: label** now ("illustrative"), optionally
   make-live later via a build-time constant. Tracked E-021.
2. **`Phase 21 active` / `BUILD Phase 21`** — `liquid-command-center-data.ts:326`. Stale phase.
   **Recommend: label** or bind to a single source of truth for phase. Tracked E-021.
3. **Gate resolution copy "audit recorded" / "approval lifecycle recorded"** —
   `WorkingCockpit.tsx:137,143`. Claims a persisted audit row that is never written.
   **Recommend: label/reword** ("simulated lifecycle — no audit row"). Tracked E-021.
4. **COST local-split hardcoded 76% when zero provider data** —
   `liquid-command-center-data.ts:450-451`. **Recommend: label/render n/a.** Tracked E-021.

Everything else synthetic in the five surfaces is synthetic **by design** with a recorded
reason (fixture headers, E-007, ID-4, Phase 22 visibility contract) and is CORRECT to stay
synthetic for the capstone — it needs labelling, not fixing.

## Honestly-empty in the current dev setup (absent ≠ broken)

- **ROOM / COST / ACTIVITY**: live only when `JARVIS_OBSERVABILITY_DB_PATH` /
  `JARVIS_EVENT_DB_PATH` names an existing sqlite (`liquid-command-center-data.ts:410-417`);
  unset in dev → synthetic readers.
- **Gateway `queue-status`**: live only when a host process injects the counts source
  (`server.ts:115-124`); no gateway host script exists in `scripts/`, so in dev the read is a
  uniform denial by design (ID-5).
- **Voice engine health**: real probes need the Chatterbox (:8004) / Kokoro (:8880) sidecars
  up and the Piper binaries on disk (`config/voice/piper-fallback.yaml`); without them the
  canonical chain honestly degrades to the Piper terminal or reports unavailable (fail-closed).
